Interfaces

Source
One place the owner's activity comes from.

Classes

ActivityRecorder
Listens to the gateway all day and writes what matters for the newsletter to the {@see DiscordActivityLog}:
ApprovalFlow
The owner-in-the-loop part: every edition is DM'd to the owner first, and only an explicit approval posts it to the newsletter channel.
Renderer
Turns drafts into Components V2 messages: the public newsletter, and the approval request DM'd to the owner (the same newsletter plus status text and Approve / Request edits / Skip buttons).
Scheduler
Fires the daily edition at the configured local time, on the bot's event loop (no cron needed), and catches up once on startup when the bot was down at the scheduled time.
Draft
One newsletter, as structured text: a headline, an intro, titled sections and a sign-off.
Env
`.env` loading for the `bot.php` / `preview.php` entry points.
JsonClient
Tiny async JSON client for the third-party APIs the newsletter reads (GitHub, Steam) and writes (GitHub contents, for the websites), driven by the bot's ReactPHP loop.
OllamaClient
Minimal async chat client for a local LLM server, driven by the bot's ReactPHP event loop.
Pipeline
Collect → write → store: turns a {@see Window} into a stored edition that is ready to be sent for approval.
ReplyInterpreter
Decides what a free-text DM reply to a draft means: approve it, reject it, or revise it (and how).
Services
Builds the environment-configured services shared by `bot.php` and `preview.php`, so both entry points read `.env` the same way.
SitePublisher
Publishes approved editions to static websites by committing them to a JSON file in each site's repository (GitHub contents API). The push to the site's branch then rebuilds and deploys it, as any other change would.
DiscordActivityLog
Append-only JSON-lines log (`var/discord-activity.jsonl`) of what the gateway saw during the day: the owner's own messages, threads and voice sessions, and periodic per-server "pulse" counters for the community as a whole.
DiscordSource
The owner's Discord activity in the servers they manage, read back from the {@see DiscordActivityLog} the bot keeps during the day, plus (optionally) moderation actions pulled from each server's audit log at digest time.
GitHubSource
The owner's GitHub activity: the user events feed (pushes, pull requests, issues, reviews, comments, releases, …) plus a commit search, which still carries commit messages when a push event's payload does not.
SourceReport
What one source found inside a {@see \Newsletter\Window}: plain-language highlight lines (the facts the LLM may use), a few headline numbers, and any errors that made the picture incomplete.
SteamSnapshots
Steam only reports lifetime playtime, so a day's playtime is the difference between two snapshots. This keeps those snapshots in the {@see StateStore}.
SteamSource
The owner's Steam activity: playtime per game inside the window (the difference between two lifetime-playtime snapshots) and achievements whose unlock time falls inside it.
StateStore
Tiny JSON-backed store (`var/state.json`) for everything that must survive a restart: editions and their approval state, the end of the last covered window, and Steam playtime snapshots.
Window
The half-open time range `[start, end)` one newsletter edition covers.
Writer
Everything the local model writes, as a short chain of small prompts (small local models do far better on several focused asks than one big one):
