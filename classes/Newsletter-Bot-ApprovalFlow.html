ApprovalFlow
in package
  • Application

FinalYes
ApprovalFlow.php : 59

The owner-in-the-loop part: every edition is DM'd to the owner first, and only an explicit approval posts it to the newsletter channel.

The owner can answer a draft three ways:

  • the buttons under it (Approve & post / Request edits / Skip);
  • a DM reply in plain words ("drop the Steam bit and mention the release"), which the local model classifies and, for edits, applies before sending a new revision for approval;
  • DM commands: !generate, !status, !publish, !help.

An approved edition is posted to the newsletter channel and, when a SitePublisher is configured, committed to each website too.

All state lives in the StateStore, and button ids carry the edition key and revision, so drafts stay actionable across restarts and a stale revision's buttons cannot post an outdated draft.
